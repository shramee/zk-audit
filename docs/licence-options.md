# Licence options

The repository has no `LICENSE` file. Choosing one is the owner's decision;
this page sets out the constraints, the options and what each one means, and
ends with a recommendation. Nothing here changes the licence.

Checked on 2026-10-29 against the repository at the `feat/product-ops`
branch (stacked on shramee/zk-audit#9 to shramee/zk-audit#15).

## Constraints on the choice

1. **The MIT inputs are compatible with every option below.** MIT text can
   be included in an MIT, Apache-2.0, AGPL or source-available project as
   long as the notice stays; `NOTICE` keeps it whatever is chosen.
2. **Keep delegating to Trail of Bits, never copy.** CC BY-SA 4.0 is
   one-way compatible with GPLv3 only; under any other choice, copied text
   would have to stay in separately licensed files.
3. **Plugin marketplace.** `claude plugin validate --profile directory`
   (Claude Code 2.1.312) reports `LICENSE_MISSING` as a problem "the plugin
   directory refuses a submission for": the plugin needs a `LICENSE` file
   (one at the repository root counts for a plugin in a sub-folder) or a
   `license` SPDX id in `plugin.json`. Without `--profile directory` the
   check is not run and validation passes, which is what CI runs today.
   The directory also warns about a missing icon (`ICON_MISSING`); that is
   independent of the licence.
4. **Users and contributors.** Without a licence nobody may legally copy,
   modify or redistribute the code; installing it from a marketplace gives
   no right to use it. Outside contributions have no inbound licence either.
5. **What the project is.** A prompt-and-tool bundle that auditors run on
   other people's code. The value is in the skill text and knowledge base as
   much as in the Go tool, so the licence covers prose as well as code.

## Options

### MIT

- Same licence as the three upstream projects and as pashov's and
  zkSecurity's skills; the shortest text; accepted everywhere, including the
  plugin directory.
- Anyone may fork it into a closed commercial product (an audit firm's
  internal tool, a paid service) without giving changes back.
- No explicit patent grant.
- To adopt: `LICENSE` with the MIT text at the root, `"license": "MIT"` in
  `plugin.json`, README section updated; `NOTICE` stays.

### Apache-2.0

- Permissive like MIT, plus an explicit patent licence from contributors and
  a patent-retaliation clause; inbound contributions are licensed on the
  same terms by default (section 5).
- Has a formal `NOTICE` mechanism (section 4(d)): redistributors must carry
  `NOTICE` forward, which protects the upstream MIT attributions without
  extra work. The repository already has a `NOTICE` file in that shape.
- Same licence as gnark, the framework this audits, and common in the
  Consensys / ZK tooling ecosystem.
- Modified files must say they were changed (section 4(b)); slightly more
  ceremony for forks than MIT.
- Closed commercial forks are allowed, as with MIT.
- To adopt: `LICENSE` with the Apache-2.0 text, `"license": "Apache-2.0"` in
  `plugin.json`, README updated; optionally an SPDX header in new files.

### AGPL-3.0 (strong copyleft, network clause)

- Anyone who modifies it and offers it to others, including as a hosted
  service, must publish their changes under AGPL. This keeps improvements
  open and stops a closed hosted "audit as a service" built on it.
- Many companies (and audit firms) have policies that forbid AGPL code, so
  adoption by the people most likely to run it would drop.
- Compatible with the MIT and BSD inputs. CC BY-SA text still could not be
  copied in (only GPLv3, not AGPLv3, is listed as compatible by Creative
  Commons).
- The plugin directory accepts it (an SPDX id), but users installing a
  skill rarely expect copyleft obligations on prompts.

### Source-available (BUSL-1.1, PolyForm Noncommercial, or similar)

- Free for non-commercial or limited use; commercial use needs a separate
  licence from the owner. BUSL-1.1 converts to an open licence (for example
  Apache-2.0) after a change date.
- Not open source (not OSI-approved). Contributions and forks drop; some
  marketplaces and users treat it as proprietary. The upstream MIT parts stay
  MIT inside it (the notice still applies), so a user may reuse those parts
  freely anyway.
- Makes sense only if the owner plans to sell commercial licences.

### Keep it unlicensed

- All rights reserved. Users have no right to run, copy or modify it beyond
  viewing and forking on GitHub under GitHub's terms.
- The plugin directory refuses the submission (`LICENSE_MISSING`).
- Contributions cannot be accepted cleanly.
- Fine while the project is private or in pilots; not fine once it is
  offered to others.

### Variant: split code and prose

Code (the Go tool, scripts, schemas) under MIT or Apache-2.0 and the skill
text and knowledge base under CC BY 4.0. Attribution follows the prose when
others reuse vectors in their own skills. It adds a second licence to
explain and a rule for every file; the gain is small unless the knowledge
base is meant to be reused on its own.

## Consequences at a glance

| | MIT | Apache-2.0 | AGPL-3.0 | Source-available | Unlicensed |
|---|---|---|---|---|---|
| Plugin directory accepts it | yes | yes | yes | yes (SPDX id, e.g. BUSL-1.1) | no (`LICENSE_MISSING`) |
| Users may run, copy, modify | yes | yes | yes, share changes | limited by terms | no |
| Closed commercial forks | allowed | allowed | changes must be published | need a licence from the owner | not allowed (nor anything else) |
| Patent grant | no | yes | yes | depends | no |
| Carries `NOTICE` forward | by convention | required | by notice requirement | by notice requirement | n/a |
| Matches upstream skills | yes (MIT) | compatible | compatible | compatible | n/a |
| Matches gnark | compatible | yes (Apache-2.0) | compatible | compatible | n/a |
| Friction for audit-firm adoption | lowest | low | high | high | blocked |

## Recommendation

**Apache-2.0**, with MIT as the close second.

- Both are permissive, compatible with every input, accepted by the plugin
  directory and by audit firms' licence policies, which is where this tool is
  most useful.
- Apache-2.0 adds what MIT lacks for a security tool in the cryptography
  space: an explicit patent grant from contributors and a clear inbound
  licence for contributions.
- Its `NOTICE` rule makes redistributors carry the zkSecurity, pashov and
  Cloudflare attributions forward, which the repository needs anyway.
- It is gnark's own licence, so code moving between gnark and this project
  (a PoC template upstreamed, a gnark test adapted into a vector) needs no
  thought.
- Choose MIT instead if matching pashov's and zkSecurity's skills exactly and
  the shortest licence text matter more than the patent grant.
- Copyleft or source-available terms would protect against closed forks but
  cut adoption by the users this skill is for; keep the project unlicensed
  only while it is private.

Whatever is chosen: keep `NOTICE`, keep delegating to Trail of Bits, add
`"license": "<SPDX id>"` to `plugin.json` next to the `LICENSE` file, and
turn on `claude plugin validate --profile directory` in CI once the file
exists (the CI step names the switch).
