# Rationalizations to reject

When you, an agent, or the code's authors reach for one of these to dismiss a
candidate, stop. None of them is a refutation. A refutation is a quoted
constraint or check that blocks the attack (`judging.md`, Gate 1).

| Rationalization | Why it fails | What to do instead |
|---|---|---|
| "The test suite passes." | Tests run honest witnesses with honest hints. An under-constrained circuit passes every honest test. | Write the malicious witness (T-HINT-OVERRIDE, T-INVALID-ASSIGNMENT). |
| "`test.IsSolved` / `assert.ProverSucceeded` is green for the bad case I tried." | They solve with the registered (honest) hints, so the bad case was never tried. | Override the hint (`solver.OverrideHint` via `test.WithSolverOpts` with `test.NoTestEngine()`). |
| "The hint computes the right value." | The prover runs its own solver and returns any outputs. Only constraints bind them. | List what the constraints force for each output. |
| "This `if` checks it." | Go control flow in `Define` runs at compile time on placeholders. | Find the constraint that enforces the condition at proving time. |
| "gnark std is audited." | GHSA-3mvx-pp85-pm65 lists 11 std bugs of exactly this shape, fixed in 2026; GHSA-7fx8 followed. Gadgets also have caller preconditions. | Check the pinned version (`gnark-versions.md`) and the gadget's contract (`gnark-api-footguns.md`). |
| "That value can never be ≥ r / negative / zero." | Field elements wrap and the prover picks the value. Zero and `r - 1` are always available. | Find the range check that rules it out. |
| "The frontend / SDK validates it." | A malicious prover skips the frontend and calls the contract or the prover API directly. | Treat every input the circuit or contract receives as attacker-chosen. |
| "Only our relayer / sequencer submits proofs." | Proofs and calldata are public in the mempool; they can be copied, replayed or front-run. Relayers can be compromised. | Check what binds the proof to the sender, recipient, chain and nonce. |
| "The verifier contract was generated by gnark, so it is fine." | It is only as good as its gnark version, its VK, its export options and how the caller builds inputs and handles the result. | Check V-VC1 to V-VC6 and the binding table. |
| "Groth16 proofs are unique, so the proof hash is a good nullifier." | gnark's prover randomises every proof; valid proofs for the same statement are easy to produce. | Key replay protection on a constrained nullifier. |
| "The signature gadget checks the signature." | It checks what its doc says. Canonical S (before v0.14.0), subgroup membership of keys, and message hashing are not all included. | Read the gadget's doc comment at the pinned version. |
| "Only the admin can call it." | The admin may be one key on a server, and admin actions can be front-run or sandwiched. A power over the verifier, roots or funds is a trust assumption users carry. | Name the amplifier (then it is a finding), or make it `needs_validation` with a `trust` object and a blocker that names the assumption (`judging.md` Gate 3). Never drop it. |
| "`zk-audit.md` says the owner is trusted." | The guidance file states intent; it does not remove the power. | Keep the record, set `trust.accepted` with the `zk-audit.md` line; the report lists it as an accepted risk. |
| "It's in the trusted setup, so it's out of scope." | A single-party `groth16.Setup` in a deploy script means one machine can forge proofs. | Check where production keys come from (V-PV1). |
| "The value is hashed, so it's bound." | A hash binds the preimage only if the preimage is fully constrained and the hash is compared with something the verifier checks. | Trace the digest to a public input or an assertion. |
| "Nobody would choose such a strange witness." | The attacker optimises for the strangest witness that verifies. | Construct it. |
| "It's only a completeness issue." | A completeness bug can brick withdrawals, and often hides a soundness bug on the other branch. | Check both branches, then judge impact. |
| "The previous audit covered it." | Prior audits describe prior code and prior gnark versions. | Re-derive it for this commit. Mark it KNOWN if it is unchanged. |
| "We'll regenerate keys later." | Old keys and deployed verifiers stay vulnerable until they are replaced. | Report the deployed state. |
